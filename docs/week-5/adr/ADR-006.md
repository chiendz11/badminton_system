## Context

Legacy auth/user duplicate identity/role; schema refresh token có token thô. Runtime mới hiện chỉ verify token, chưa có Identity issuer.

## Options

| Phương án | Trade-off |
| --- | --- |
| Giữ Auth và User hai nguồn ghi | Role/active status có thể lệch. |
| Gộp Identity, tương thích claim hiện tại | Chọn bước đầu; giảm drift và không sửa validator tùy ý. |
| Chuyển ngay JWKS/RS256 | Tốt cho key isolation nhưng cần rollout mọi verifier và rotation protocol. |

## Proposed decision

Identity gộp account/profile/session/OAuth/role; lowercase roles user/center_manager/super_admin. Claims sub/role/iss/aud/exp tương thích hiện tại, key algorithm transition thành PR riêng. Password/refresh/client secrets hash, rotation/reuse detection. Resource ACL bổ sung role check.

## Consequences và điều kiện cần chốt

Center assignment và ownership kiểm server. Không cấp super_admin qua update profile. Không diễn giải legacy userId claim như sub mà không có mapping. Việc revoke cần policy TTL/introspection/projection được duyệt.

## Migration / rollback

Map public ID và roles trước cutover; verify old/new signing keys có thời hạn nếu chọn migration. Không khôi phục plaintext token store hoặc mặc định tin header actor khi lỗi Identity.
